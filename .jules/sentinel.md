## 2025-02-18 - Prevent Key-Length Leakage and Timing Attacks in API Key Validation
**Vulnerability:** Direct string length checks (`provided.length !== expected.length`) and calling `crypto.timingSafeEqual` directly on unhashed user-controlled strings can leak the exact length of secret API keys via timing side channels and/or crash the runtime due to buffer length mismatches.
**Learning:** Checking the input lengths beforehand allows an attacker to brute force the correct API key length because the server responds much quicker when the length is wrong. Moreover, `crypto.timingSafeEqual` throws an error if buffer lengths are different, which developers often try to avoid by doing early length checks.
**Prevention:** To safely use `crypto.timingSafeEqual` with potentially different input lengths without leaking information, hash both the provided and expected values using a cryptographic hash function like SHA-256 first. Since the hash digests will always be equal in length (32 bytes), they can be compared in constant time with `timingSafeEqual` without any preliminary length checks.
